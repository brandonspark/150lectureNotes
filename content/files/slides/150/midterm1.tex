\titledquestion{Binary Search Trees}

\textbf{Binary Search Trees}

Recall the type of \code{tree}s, from lecture:
\begin{codeblock}
  datatype tree = Empty | Node of tree * int * tree
\end{codeblock}

A \textit{binary search tree} is a value of the \code{tree} type, that satisfies the
following definition:

\textbf{Definition.} A value \code{v : t} is called a \textit{binary search tree} if:
\begin{enumerate}
  \item It is \code{Empty}.
  \item It is \code{Node (L, x, R)}, where both \code{L} and \code{R} are binary search trees,
  and \code{x} is greater than or equal to every element in \code{L}, and less than or
  equal to every element in \code{R}.
\end{enumerate}


\begin{parts}
  \part[5]\hfill

  Implement a function \code{isGeqTree} which adheres to the following specification:

  \spec
    {isGeqTree}
    {int * tree -> bool}
    {\code{true}}
    {\code{isGeqTree (x, T)} evaluates to \code{true} iff \code{x} is greater than
    or equal to every element of \code{T}.}

  \begin{solutionorbox}[25em]
    \begin{codeblock}
      fun isGeqTree (n : int, Empty : tree) : bool = true
        | isGeqTree (n, Node (L, x, R)) =
            n >= x andalso isGeqTree (n, L) andalso isGeqTree (n, R)
    \end{codeblock}
  \end{solutionorbox}

  \begin{EnvUplevel}
    Assuming that we have implemented an analogous \code{isLeqTree} function,
    with the following specification:

    \vspace{7pt}
    \begin{adjustwidth}{0em}{0em} % adjust the left margin to 2em
    \spec
      {isLeqTree}
      {int * tree -> bool}
      {\code{true}}
      {\code{isLeqTree (x, T)} evaluates to \code{true} iff \code{x} is less than
      or equal to every element of \code{T}.}
    \end{adjustwidth}

    then we can define our \code{isBST} function with the following specification:

    \vspace{7pt}
    \begin{adjustwidth}{0em}{0em} % adjust the left margin to 2em
    \spec
      {isBST}
      {tree -> bool}
      {\code{true}}
      {\code{isBST T} evaluates to \code{true} iff \code{T} is a binary search tree.}
    \end{adjustwidth}

    % TODO: could give to them?
    \begin{codeblock}
      fun isBST (Empty : tree) : bool = true
        | isBST (Node (L, x, R)) =
            isBST L andalso isBST R
            andalso isGeqTree (x, L) andalso isLeqTree (x, R)
    \end{codeblock}
  \end{EnvUplevel}

  \part[3]\hfill

  Assuming that the work of both \code{isGeqTree} and \code{isLeqTree} are
  $O(n)$ in the number of nodes in the tree, write a recurrence for the \textbf{work}
  of \code{isBST}, in terms of $n$, the \textbf{number of nodes} in the input tree, when given
  a \textbf{balanced} tree. You do not need to give a bound.

  \begin{solutionorbox}[20em]
    \begin{align*}
      &W_{\code{isBST}}(0) = c_0 \\
      &W_{\code{isBST}}(n) = 2W_{\code{isBST}}(\frac{n}{2}) +
      W_{\code{isLeqTree}}(\frac{n}{2}) + W_{\code{isGeqTree}}(\frac{n}{2}) + c_1 \\
    \end{align*}
  \end{solutionorbox}

  \newpage

  \part[5]\hfill

  Solve the recurrence from the previous part to obtain a bound in
  $n$. \textbf{Show your work!} You may combine terms of the same asymptotic complexity
  together to simplify your analysis.

  \begin{solutionorbox}[25em]
    By the Tree Method.

    We note that there are $\log n$ levels, $2^i$ nodes per level, and

  \end{solutionorbox}

\titledquestion{Binary Search Trees, Better}

\textbf{Binary Search Trees, Better}

That's a pretty silly way to do \code{isBST}. Let's try via a different
method.

Recall the \textit{inorder traversal} of a tree, which looks something like this:

\begin{center}
  \begin{tikzpicture}
    [level distance=12mm,
    every node/.style={circle,inner sep=3pt, draw=black!80, thick},
    level 1/.style={sibling distance=24mm},
    level 2/.style={sibling distance=12mm},
    ]
    \node {4}
      child {node {2}
        child {node {1}}
        child {node {3}}
      }
      child {node {6}
        child {node {5}}
        child {node {7}}
      };
    \end{tikzpicture}
\end{center}

It just so happens that, if a tree is a binary
search tree, then an inorder traversal of that tree should only visit
nodes in a nondecreasing order.

\begin{parts}

  \part[6]\hfill

  Write a function \code{isNondecreasing}, which satisfies the following
  specification:

  \spec
    {isNondecreasing}
    {int list -> bool}
    {\code{true}}
    {\code{isNondecreasing L} evaluates to \code{true} iff all the elements
    of \code{L} are present in nondecreasing order, from left to right.}

  Test cases:
  \begin{itemize}
    \item \code{isNondecreasing []} $\hookrightarrow$ \code{true}
    \item \code{isNondecreasing [1]} $\hookrightarrow$ \code{true}
    \item \code{isNondecreasing [1, 2, 2, 3]} $\hookrightarrow$ \code{true}
    \item \code{isNondecreasing [1, 3, 2, 4]} $\hookrightarrow$ \code{false}
  \end{itemize}

  \begin{constraint}
    \code{isNondecreasing} must be implemented in $O(n)$ in the length
    of the input list.
  \end{constraint}

  \textbf{Extra credit (2 points):} Implement \code{isNondecreasing}
  in a tail recursive manner. You may use a helper function.

  \begin{solutionorbox}[15em]
    \begin{codeblock}
      fun isNondecreasing ([] : int list) = true
        | isNondecreasing [x] = true
        | isNondecreasing (x::y::ys) =
            x <= y andalso isNondecreasing (y::ys)
    \end{codeblock}

    Tail recursive version:
    \begin{codeblock}
      fun aux ([] : int list, acc : bool) = acc
        | aux ([x], acc) = acc
        | aux (x::y::ys, acc) =
            aux (y::ys, acc andalso x <= y)

      fun isNondecreasing (L : int list) = aux (L, true)
    \end{codeblock}
  \end{solutionorbox}

  \begin{EnvUplevel}
    With the \code{isNondecreasing} function, we can simply define
    \code{isBST} as follows:

    \begin{codeblock}
      fun isBST (T : tree) = isNondecreasing (inord' T)
    \end{codeblock}

    Suppose we were given the following implementation of \code{inord'}:

    \begin{codeblock}
      fun inord' (Empty : tree, acc) : int list = acc
        | inord' (Node (L, x, R), acc) =
            inord' (L, x :: inord' (R, acc))
    \end{codeblock}

\textbf{To the Max}

\begin{parts}
  \part[8]\hfill

  Write a function \code{tlistmax}, satisfying the following specification:

  \spec
    {tlistmax}
    {int list * int option -> int option}
    {\code{true}}
    {
      \code{tlistmax (L, acc)} $\eeq$

      \vspace{3pt}

      $\left\{
        \begin{array}{@{}l l@{}}
            \code{NONE}, & \text{if } \code{L} \eeq \code{[]} \text{ and } \code{acc} \eeq \code{NONE} \\
            \code{SOME x}, & \text{if } \code{acc} \eeq \code{SOME y}\text{, where }
            \code{x}\text{ is the max element of } \code{y::L} \\
            \code{SOME x}, & \text{if } \code{acc} \eeq \code{NONE}\text{, where }
            \code{x}\text{ is the max element of } \code{L}
        \end{array}
      \right\}
      $
    }

  You may assume that you have been given a function
  \code{max : int * int -> int} which simply computes the maximum of two integers.

  \vspace{3pt}

  Test cases:
  \begin{itemize}
    \item \code{tlistmax ([], NONE)} $\hookrightarrow$ \code{NONE}
    \item \code{tlistmax ([], SOME 5)} $\hookrightarrow$ \code{SOME 5}
    \item \code{tlistmax ([1], SOME 0)} $\hookrightarrow$ \code{SOME 1}
    \item \code{tlistmax ([1, 2, 3], NONE)} $\hookrightarrow$ \code{SOME 3}
    \item \code{tlistmax ([1, 2, 3], SOME 999)} $\hookrightarrow$ \code{SOME 999}
  \end{itemize}

  \begin{constraint}
    \code{tlistmax} must be tail recursive.
  \end{constraint}

  \begin{solutionorbox}[25em]
    \begin{codeblock}
      fun tlistmax ([] : int list, acc : int option) : int option = acc
        | tlistmax (x::xs, acc) =
            case acc of
              NONE => tlistmax (xs, SOME x)
            | SOME y => tlistmax (xs, SOME (max (x, y)))
    \end{codeblock}
  \end{solutionorbox}

  \part[8]\hfill

  We're also interested in writing a max function on trees.

  \spec
    {treemax}
    {tree -> int option}
    {\code{true}}
    {\code{treemax T} evaluates to the maximum element of \code{T}, or \code{NONE} if \code{T} is empty.}

  Implement the above function. To make our code nicer, we will
  first write a helper function \code{max_opt : int option * int option -> int option}.

  \begin{codeblock}
      fun max_opt (x : int option, y : int option) : int option =
        case (x, y) of
          (* code below *)
  \end{codeblock}

  \begin{solutionorbox}[15em]
    \begin{codeblock}
          (NONE, NONE) => NONE
        | (SOME x, NONE) => SOME x
        | (NONE, SOME y) => SOME y
        | (SOME x, SOME y) => SOME (max (x, y))
    \end{codeblock}
  \end{solutionorbox}

  Now implement \code{treemax} using \code{max_opt}:

  \begin{codeblock}
    fun treemax (Empty : tree) : int option = NONE
      | treemax (Node (L, x, R)) =
          (* code below *)
  \end{codeblock}

  \begin{solutionorbox}[10em]
    \begin{codeblock}
          max_opt (SOME x, max_opt (treemax L, treemax R))
    \end{codeblock}
  \end{solutionorbox}
\end{parts}

\titledquestion{Inserting Two Ways}

\textbf{Inserting Two Ways}

Recall that in a sorted data structure, we can insert an element into
it in a way that maintains the sorted order, in linear time.

See the following implementations of insertion on sorted lists and trees,
given by \code{linsert} and \code{tinsert} respectively.

\begin{codeblock}
  fun linsert (x : int, [] : int list) : int list = [x]
    | linsert (x, y::ys) =
        if x <= y then
          x::y::ys
        else
          y :: linsert (x, ys)
\end{codeblock}

\begin{codeblock}
  fun tinsert (x : int, Empty : tree) : tree =
        Node (Empty, x, Empty)
    | tinsert (x, Node (L, y, R)) =
        if x <= y then
          Node (tinsert (x, L), y, R)
        else
          Node (L, y, tinsert (x, R))
\end{codeblock}

Recall also the function for computing the \emph{inorder traversal} of
a tree:
\begin{codeblock}
  fun inord (Empty : tree) : int list = []
    | inord (Node (L, x, R)) = inord L @ [x] @ inord R
\end{codeblock}

\begin{parts}
  \part[20]\hfill

  Prove the following theorem:

  For all values \code{T : tree} and \code{v : int}:
  $$\code{inord (tinsert (v, T))} \eeq \code{linsert (v, inord T)}$$

  You may use the following lemmas in your proof:

  \textbf{Lemma 1:} \code{inord} is total.

  \textbf{Lemma 2:} \code{tinsert} and \code{linsert} are total.

  \textbf{Lemma 3:} For values \code{L1, L2 : int list} and \code{v, x : int}, if \code{v} $\leq$ \code{x},
  then $$\code{linsert (v, L1 @ [x] @ L2)} \eeq \code{linsert(v, L1) @ [x] @ L2}$$

  \textbf{Lemma 4:} For a value \code{L : int list}, $\code{L @ []} \eeq \code{L}$

  \begin{constraint}
    In the recursive case, only prove the theorem for when we insert a value into the left subtree!
  \end{constraint} \\

  Please write your proof on the next page.\footnote{Phenomenal cosmic power, itty-bitty writing space.}

  % \begin{center}
  %   \begin{tikzpicture}[
  %     every node/.style={font=\small},
  %     arr/.style={->, >=stealth, thick},
  %     node distance=2.5cm and 4cm,
  %   ]
  %     \node (TL) {\code{T}};
  %     \node (TR) [right=of TL] {\code{tinsert (v, T)}};
  %     \node (BL) [below=of TL] {\code{inord T}};
  %     \node (BR) [below=of TR] {\code{linsert (v, inord T)}};

  %     \draw[arr] (TL) -- node[above] {\code{tinsert (v, $\cdot$)}} (TR);
  %     \draw[arr] (TL) -- node[left]  {\code{inord}}                (BL);
  %     \draw[arr] (TR) -- node[right] {\code{inord}}                (BR);
  %     \draw[arr] (BL) -- node[below] {\code{linsert (v, $\cdot$)}} (BR);
  %   \end{tikzpicture}
  % \end{center}

  \begin{solutionorbox}[50em]
    By structural induction on \code{T : tree}.

    BC: \code{T = Empty}

    LHS:
    \begin{align*}
      & \code{inord (tinsert (v, Empty))} \\
      &= \code{inord (Node (Empty, v, Empty))} \tag{clause 1 of \code{tinsert}} \\
      &= \code{inord Empty @ [v] @ inord Empty} \tag{clause 2 of \code{inord}} \\
      &= \code{[] @ [v] @ []} \tag{clause 1 of \code{inord}} \\
      &= \code{[v]} \tag{lemma 4, clause 1 of \code{@}} \\
    \end{align*}

    RHS:
    \begin{align*}
      & \code{linsert (v, inord Empty)} \\
      &= \code{linsert (v, [])} \tag{clause 1 of \code{inord}} \\
      &= \code{[v]} \tag{clause 1 of \code{linsert}} \\
    \end{align*}

    IH1: \code{inord (tinsert (v, L))} $\eeq$ \code{linsert (v, inord L)} \\
    IH2: \code{inord (tinsert (v, R))} $\eeq$ \code{linsert (v, inord R)}

    IS: Let \code{T = Node (L, x, R)} for some \code{x : int} and \code{L, R : tree}.

    WTS: \code{inord (tinsert (v, Node (L, x, R)))} $\eeq$ \code{linsert (v, inord (Node (L, x, R)))}

    Case 1: \code{v} $\leq$ \code{x}

    LHS:
    \begin{align*}
      & \code{inord (tinsert (v, Node (L, x, R)))} \\
      &= \code{inord (Node (tinsert (v, L), x, R))} \tag{clause 2 of \code{tinsert}} \\
      &= \code{inord (tinsert (v, L)) @ [x] @ inord R} \tag{clause 2 of \code{inord}, totality of \code{tinsert}} \\
      &= \code{linsert (v, inord L) @ [x] @ inord R} \tag{induction hypothesis} \\
    \end{align*}

    RHS:
    \begin{align*}
      & \code{linsert (v, inord (Node (L, x, R)))} \\
      &= \code{linsert (v, inord L @ [x] @ inord R)} \tag{clause 2 of \code{inord}}\\
      &= \code{linsert (v, inord L) @ [x] @ inord R} \tag{lemma 3, totality of \code{inord}, case assumption} \\
    \end{align*}
  \end{solutionorbox}

  \makeemptybox{50em}
\end{parts}

\titledquestion{Extra Credit: Exam Design}
\textbf{Extra Credit: Exam Design}

Brandon is writing a 15-150 exam! He needs your help to come up with a
type for the exam, or else it may not be ready in time on
June 8th, 2026 to give to his students\footnote{\color{blue}\url{https://en.wikipedia.org/wiki/Circular_definition}}.
\vspace{-15pt}
\begin{center}
\includegraphics[width=0.99\textwidth]{img/exam_type.png}
\end{center}
Every top-level problem has a positive point value, a title (a string), and
one of the following forms:

\begin{itemize}
  \item a \textbf{type-and-value} problem, which presents an SML
  expression to give the type and value of.
  \item a \textbf{code-writing} problem, which presents a function
  specification (a function name, its type, its REQUIRES, and its ENSURES) to implement.
  \item an \textbf{equivalence proof} problem, which presents two SML expressions to
  prove extensionally equivalent. Proof problems may also come with
  some number of lemmas the student may use.
  \item a \textbf{compound} problem, which consists of two or more
  sub-problems. Each sub-problem is itself a 15-150 exam problem, but \textbf{not a top-level one}
  (i.e. sub-problems do not have point values or titles).
  \item in addition, an exam \textbf{may} have an extra-credit problem (but only one!).
\end{itemize}

For this problem, you may assume that an SML expression, a type, a
REQUIRES, an ENSURES, and a theorem statement are each represented as a
string.

\newpage

\begin{parts}
  \bonuspart[5]\hfill

    Come up with a type \code{exam} that faithfully
    represents the above. This type should have \textbf{minimal illegal states},
    meaning that values of this type should represent all and only
    the relevant information to a valid exam.

    It should also be \textbf{as un-redundant as possible}, meaning there should
    not be different values that represent the same exam. It should also be as simple and elegant as possible.

    You may use as many \code{type} and \code{datatype} declarations as
    you wish.

    \begin{solutionorbox}[40em]
      \begin{codeblock}
        type spec = string * string * string * string
          (* name, type, REQUIRES, ENSURES *)

        datatype problem =
            TypesAndValue of string
          | CodeWriting of spec
          | Proof of string * string * string list
              (* lhs, rhs, lemmas *)
          | Compound of problem * problem * problem list

        type top_level_problem = int * string * problem
          (* points, title, kind *)

        type exam = top_level_problem list
                  * top_level_problem option
          (* problems, optional extra credit *)
      \end{codeblock}

      The compound case using \code{top_level_problem * top_level_problem * top_level_problem list}
      enforces ``two or more'' --- a \code{top_level_problem list} would admit
      \code{[]} and singletons.
    \end{solutionorbox}
\end{parts}
